# 查找

把「在一个集合里找目标」分成三类：直接在数据上扫（顺序）、用哈希把 key 映射到位置、用单调性跳着找（二分）。

---

## 顺序查找

**思路**：从左到右逐一比对。最朴素但通用（不要求有序）。

**模板**：

```java
for (int i = 0; i < a.length; i++) {
  if (a[i] == target) return i;
}
return -1;
```

**哨兵优化**（少一次 `i < n` 判断）：把 `target` 暂存到 `a[n]`，循环里只判 `a[i] == target`，返回前还原。

- **时间**：O(n)
- **空间**：O(1)
- **适用**：小数组、几乎不命中、无序数据

---

## 哈希查找

**思路**：哈希函数把 key 映射到数组下标，平均 O(1) 定位。冲突处理两种思路：拉链法（数组每个槽挂链表）与开放定址（探测下一个空槽）。

**模板**（链地址 / `HashMap` 视角）：

```java
Map<Integer, Integer> idx = new HashMap<>();
for (int i = 0; i < a.length; i++) idx.put(a[i], i);
// 查询
Integer pos = idx.get(target);
return pos == null ? -1 : pos;
```

**冲突与负载因子**：装载超过 ~0.75 时 rehash，期望查找长度 O(1)；极端情况下所有 key 落到同一槽 → O(n)。

**常见错误**：
- 自定义 `hashCode` 未与 `equals` 一致（`HashMap` 退化）
- 用可变对象做 key（put 后改字段，丢失定位）

- **时间**：平均 O(1)，最坏 O(n)
- **空间**：O(n)

---

## 二分查找

在**有序**数组（或具有单调性的答案空间）上，每次排除一半区间，将 O(n) 线性扫描降为 O(log n)。

**前提**：下标 `0..n-1` 上数组单调非降（或问题具有「越界一侧必错」的单调性）。

**模板要点**：

1. 维护搜索区间 `[lo, hi]`（闭区间）或 `[lo, hi)`（半开）
2. 取 `mid`，根据与 `target` 的关系收缩区间
3. 循环条件：`lo <= hi` 或 `lo < hi`，二者与边界更新必须配对

```java
int lo = 0, hi = n - 1;
while (lo <= hi) {
  int mid = lo + (hi - lo) / 2;
  if (a[mid] == target) return mid;
  if (a[mid] < target) lo = mid + 1;
  else hi = mid - 1;
}
return -1;
```

- **时间**：O(log n)
- **空间**：O(1)

## 边界与变体

| 问题 | 思路 |
|------|------|
| 第一个 ≥ x 的位置 | `hi = mid` 或 `lo = mid + 1`，看 `a[mid] < x` |
| 最后一个 ≤ x 的位置 | 对称写法 |
| 答案在实数域 | 对答案二分，写 `check(mid)` 判定可行性 |
| 山脉数组找峰 | 上下坡单调性二分 |

**常见错误**：`mid = (lo + hi) / 2` 溢出（用 `lo + (hi-lo)/2`）；死循环（`lo/hi` 更新未严格缩小区间）。

## KMP：next 数组与字符串匹配

>（by Mako800大佬 github同名）

### 先理解：为什么需要 next？

KMP 用来解决这样的问题：

> **在主串 `T` 中寻找模式串 `S` 的出现位置。**

如果匹配过程中发生失配，一个朴素的做法是让模式串重新移动，再从头比较。

但这样会重复比较已经比较过的字符。

KMP 的关键想法是：

> **前面已经匹配成功的部分并不是没有用的。**

如果这部分字符串的**前缀和后缀有相同的部分**，那么失配之后，就可以直接利用这部分信息，而不需要从头开始。

因此，我们需要提前计算一个 `next` 数组。

---

### 一、next 是什么？

`next[i]` 表示：

> **字符串 `S[1..i]` 的最长公共前后缀的长度。**

所谓“公共前后缀”，就是一段字符串同时是 `S[1..i]` 的前缀和后缀。

例如：

```text
S = a b c d a b c ...

    └───┬──┘    └───┬──┘
        a b c       a b c

        ↑───────────↑
        一对公共前后缀
```

这里 `abc` 同时出现在开头和结尾，因此它是一对公共前后缀。

而 `next[i]` 记录的，就是其中**最长的那一对的长度**。

---

### 二、如何求 next？

现在要求 `next[i]`。

假设：

> **`next[1..i-1]` 都已经求出来了。**

我们已经知道 `S[1..i-1]` 的最长公共前后缀。

```text
┌──────────────────────┐   ┌──────────────────┐   ┌───┐
│  ┌──────────┐        │   │  ┌──────────┐    │   │ ★ │
│  │   红框   │   Δ    │   │  │   红框   │    │   │   │
│  └──────────┘        │   │  └──────────┘    │   │   │
└──────────────────────┘   └──────────────────┘   └───┘
                                                   i
```

红框表示 `S[1..i-1]` 的一对**最长公共前后缀**。

现在只需要看：

> **`Δ` 和 `★` 这两个字符是否相同。**

#### 情况 ①：相同

如果：

```text
Δ == ★
```

那么原来的最长公共前后缀可以直接向后延长一个字符。

所以：

```text
next[i] = next[i-1] + 1
```

---

#### 情况 ②：不同

如果：

```text
Δ != ★
```

说明当前最长公共前后缀不能继续延长。

但这并不意味着答案只能从头重新找。

因为：

> **原来的最长公共前后缀内部，可能还存在更短的公共前后缀。**

于是我们继续寻找：

```text
S[1..next[i-1]]
```

的最长公共前后缀。

```text
┌──────────────────────┐   ┌──────────────────┐   ┌───┐
│  ┌──────────┐        │   │  ┌──────────┐    │   │ ★ │
│  │ ○  □  ○  │        │   │  │ ○     ○  │    │   │   │
│  └──────────┘        │   │  └──────────┘    │   │   │
└──────────────────────┘   └──────────────────┘   └───┘
                                                   i
```

图中的 4 个 `○` 都表示相同的字符。

此时只需要比较：

> **`□` 和 `★` 是否相同。**

#### 如果相同

那么又可以延长：

```text
next[i] = next[next[i-1]] + 1
```

#### 如果仍然不同

同样的思路继续：

> **沿着 `next` 不断寻找更短的公共前后缀。**

也就是递归式地：

```text
next[i-1]
    ↓
next[next[i-1]]
    ↓
next[next[next[i-1]]]
    ↓
    ...
```

直到：

* 找到可以匹配的字符 → 得到 `next[i]`
* 或者不存在更短的公共前后缀，即找到某个 `next[j] = 0`

---

### 三、next 数组有什么用？

求出 `next` 之后，就可以用它来进行 KMP 匹配。

它最大的作用是：

> **匹配失败之后，可以跳过已经知道的信息。**

例如，在主串：

```text
t a b c d a b c e a b c d a b c f
```

中寻找：

```text
a b c d a b c f
```

前面已经匹配成功：

```text
a b c d a b c
```

当比较到：

```text
主串：   ... a b c e
                  ↑
模式串： ... a b c f
                  ↑
```

发现：

```text
e ≠ f
```

发生失配。

---

#### 为什么可以直接跳？

已经匹配成功的：

```text
a b c d a b c
```

中，前面的：

```text
a b c
```

和后面的：

```text
a b c
```

是一对公共前后缀。

所以我们知道：

> 后面的 `abc` 已经与主串对应位置匹配过了，不需要再比较一次。

因此，不必让主串指针往回移动，也不必一个个重新比较。

直接跳到：

```text
主串：   t a b c d a b c e a b c d a b c f
                              ↓
模式串：                 a b c d a b c f
                         ───────  ───────
                         已知相同的部分
```

可以看到：

> **主串指针 `↓` 不需要左移。**

这正是 KMP 的核心优势。

因为主串指针始终向右移动，所以整个匹配过程的时间复杂度可以做到：

> **O(n + m)**

其中 `n` 是主串长度，`m` 是模式串长度。

---

### 四、实例：求出整个 next 数组

现在实际看一个例子：

```text
       1  2  3  4  5  6  7  8
S =    a  b  a  c  a  b  a  d
```

假设我们已经求出了：

```text
       1  2  3  4  5  6  7  8
S =    a  b  a  c  a  b  a  d
next = 0  0  1  0  1  2  ?  ?
```

现在要求 `next[7]`。

---

#### 求 next[7]

我们已经知道：

```text
next[6] = 2
```

因此先看：

```text
S[next[6] + 1]
= S[3]
= a
```

而：

```text
S[7] = a
```

所以：

```text
S[3] == S[7]
```

可以直接延长。

因此：

```text
next[7] = next[6] + 1
        = 2 + 1
        = 3
```

得到：

```text
       1  2  3  4  5  6  7  8
S =    a  b  a  c  a  b  a  d
next = 0  0  1  0  1  2  3  ?
```

---

#### 求 next[8]

现在：

```text
next[7] = 3
```

先比较：

```text
S[next[7] + 1]
= S[4]
= c
```

和：

```text
S[8] = d
```

发现：

```text
c ≠ d
```

所以不能直接延长。

沿着 `next` 继续寻找更短的公共前后缀：

```text
next[next[7]]
= next[3]
= 1
```

于是比较：

```text
S[next[3] + 1]
= S[2]
= b
```

和：

```text
S[8] = d
```

仍然：

```text
b ≠ d
```

继续：

```text
next[1] = 0
```

已经不存在更短的公共前后缀。

因此：

```text
next[8] = 0
```

最终得到：

```text
       1  2  3  4  5  6  7  8
S =    a  b  a  c  a  b  a  d
next = 0  0  1  0  1  2  3  0
```

---

### 最后记住 KMP 的两件事

#### 求 next

> **失配了，就沿着 next 找更短的公共前后缀。**

#### 做匹配

> **失配了，就利用 next 跳过已经知道的信息，主串指针不回退。**

**next 数组的本质，就是提前记录：**

> **”如果这里失配了，我还能保留多少已经匹配的信息？”**
