> 2026-07-13 更新

## 〇、与现有代码 Agent 的对比

市面上已有 Claude Code、GitHub Copilot、Cursor 等代码 Agent，但它们和 JavaTutor 的目标完全不同：

| | Claude Code / Copilot / Cursor | JavaTutor 智能体 |
|------|------|------|
| **定位** | 帮开发者写代码、提效 | 帮学生**理解代码执行过程** |
| **能看到的** | 静态源码 | 源码 + **每一步的变量快照 + 行号** |
| **回答方式** | 基于静态推理："这个循环理论上会执行 n 次" | 基于实际数据："第 5 步循环时 i=3，arr[3]=7，因为它刚和第 4 步的 arr[2]=5 交换了" |
| **运行代码** | 可以，但要用户手动跑 | **自动**：点"运行"即插桩执行并采集全量 steps |
| **算法教学** | 能解释原理，画 Mermaid 图 | 能解释 + 用**真实运行数据生成专属动画** |
| **记忆** | 无跨会话记忆 | 记住学生的学习轨迹和薄弱点 |

**核心差异一句话**：通用代码 Agent 是"帮你写代码的工具"，JavaTutor 是"帮你理解代码为什么这么执行的老师"。前者看不到运行时，后者把运行时作为第一手数据。

## 一、智能体定位

**基于 TraceEngine 运行时数据的自由问答 + 算法动画生成 + 个性化教学记忆。**

三个核心能力：

| 能力 | 说明 | 与通用 AI 的区别 |
|------|------|-----------------|
| **自由问答** | 学生调试时可追问任何与执行过程相关的问题 | 通用 AI 只能静态推理源码；这个智能体能看到每一步的变量快照和行号 |
| **算法动画** | 基于用户实际运行数据，生成该算法的形象演示动画 | 通用 AI 无法拿到 TraceEngine 的真实 steps 数据，生成不了"这段代码"的专属动画 |
| **教学记忆** | 跨会话记住学生的学习轨迹和薄弱点 | 通用 AI 每次对话从零开始；这个智能体知道你上次卡在哪里 |

## 二、上下文数据

智能体可调用的数据：

| 数据 | 来源 |
|------|------|
| 完整源代码 | 前端 Monaco Editor |
| 全部执行步骤（steps） | TraceEngine.getSteps() |
| 当前步骤的变量快照 | steps[currentStep].variables |
| 当前高亮行号 + 行文本 | steps[currentStep].line |
| 编译错误信息 | InMemoryCompiler 异常 |
| 算法标签 + 复杂度 | AnalyzeService |
| 控制流图数据 | ControlFlowService |
| 用户身份（user_id） | 前端 localStorage UUID |

## 三、功能

### A. 自由问答（核心 + 多智能体路由）

学生在调试的任意时刻打开对话面板，追问任何与当前执行相关的问题。

```
前端 ChatPanel → POST /api/chat（SSE 流式）
  → 后端拼 prompt：全量 steps + 源码 + 用户问题 + user_id
  → Coze Bot API → 流式返回
```

**多智能体路由**：一个入口 Bot 负责路由，根据学生问题类型分派给不同子 Bot：
- "为什么 arr[3] 是 7？" → 数据追问专家（擅长对照 TraceEngine 数据回答）
- "这段代码编译报错了" → 诊断专家（擅长解释 javac 错误信息）
- "冒泡排序的原理是什么？" → 算法讲解专家（擅长用通俗语言解释算法）
- "帮我生成一个动画" → 触发 Workflow

用多智能体而非一个大而全的 System Prompt，避免"一个老师同时教语文数学英语"导致回答风格混乱。

### B. 编译错误诊断

代码编译失败时，智能体拿到编译错误原文，用中文解释原因 + 给出修改建议 + 指出错误行。

触发：`RunController` 编译失败分支自动调用。

### C. 算法动画生成（核心）

不同于变量卡片的"数据可视化"（arr[2] 从 5 变成了 7），动画做**算法可视化**——让用户看到"最高的柱子从左边冒泡到了右边"，形象理解算法过程。

#### 视觉隐喻

| 算法类别 | 视觉隐喻 | 输出格式 |
|---------|---------|:---:|
| 排序（冒泡/快排/选择/插入） | 柱状图，比较时高亮，交换时柱子左右滑动 | SVG |
| 搜索（二分/线性） | 柱状图 + 扫描线从左到右移动 | SVG |
| 树遍历（BFS/DFS/前中后序） | 节点圆点按遍历顺序逐一亮起 | SVG |
| 图算法（Dijkstra/Prim） | 节点 + 边，最短路径逐步染色 | SVG |
| 动态规划 | 表格，逐格填入值，当前格高亮 | SVG |
| 链表操作 | 节点方块 + 指针箭头移动 | SVG |

#### 为什么用 SVG 而不用多模态生成

多模态模型（视频生成）做算法动画有根本矛盾：**算法动画要求精确（柱高 50px = 值 5），多模态生成本质是近似（噪声中猜测像素大致长什么样）。** 它会生成"看起来像冒泡排序的画面"而非"你这段代码的准确执行过程"。

SVG 则不同——柱高直接从数据计算，动画时间轴从步骤顺序生成。Coze 的 LLM 只做"格式转换"（把数据填入模板），不做"视觉创作"。

#### 为什么不用 JSON 帧数据

JSON 帧数据与变量卡片高度重叠——两者都是 "Step N 时 arr 是什么值"，只是换了个形状。变量卡片已经解决了数据可视化，动画要解决的是变量卡片做不了的事：**元素在空间中的连续移动**——柱子真的从左边滑到右边。

#### 技术方案

```
算法标签 + steps 数据
       │
       ▼
Coze Workflow
  ├── ① 知识库检索：根据算法标签匹配 SVG 模板
  ├── ② LLM 节点：把用户真实数据填入模板占位符
  └── ③ 输出：内嵌 SMIL 动画的 SVG 文本
       │
       ▼
前端
  ├── 预览：<div v-html="svgText"> 直接渲染，浏览器原生播放
  └── 下载：Blob → .svg 文件，学生双击即播
```

#### SVG SMIL 动画能力

SVG 内置 SMIL 动画引擎，浏览器原生支持，不需要任何外部库：

| 能力 | 标签 | 用途 |
|------|------|------|
| 位置变化 | `<animate attributeName="x">` | 柱子左右交换 |
| 大小变化 | `<animate attributeName="height">` | 柱子变高 |
| 颜色变化 | `<animate attributeName="fill">` | 比较高亮 → 归位熄灭 |
| 顺序播放 | `begin="0s"`, `begin="2s"` | 先交换第一对，再交换第二对 |

#### 模板管理

知识库存放每种算法的 SVG 模板（骨架 + 时间轴 + 占位符）。LLM 只做填空：把占位符替换为用户真实数据。这与 Mermaid → 控制流图的逻辑完全一致——模板保证精确，LLM 只负责数据映射。

#### 箭头方案的教训

之前 LinkedListCanvas 用"DOM 画节点 + SVG 画箭头"失败的根本原因：**两个坐标系需要实时对齐，CSS 动画和 JS 测量永远不同步。** 此次动画方案吸取教训——全 SVG 或全 DOM，不混合坐标系。SVG 的优势是柱状图/节点树这类场景不存在"浏览器自动布局"，每个元素的位置从数据直接算出，零测量、零对齐。

### D. 个性化教学记忆

智能体跨会话记住学生，对话不是每次从零开始。

**技术基础**：
- 前端 `localStorage` 存 UUID → 作为 `user_id` 传给后端 → 后端调 Coze API 时传入
- Coze 侧开启**长期记忆**（自动提取关键信息）+ **用户变量**（结构化存储学习进度）

**存储内容**：

| 机制 | 谁控制 | 内容示例 |
|------|------|------|
| 长期记忆 | Coze 自动 | "该学生循环边界条件反复出错""问过两次 HashMap 原理" |
| 用户变量 | 开发者 Set/Get | 技能等级、已学算法列表、常见错误标签、累计会话次数 |

**具体表现**：
```
第一次会话：
  "冒泡排序外层循环 j<arr.length-1 少减了 i"
  → 记忆库自动记录：loop_boundary 薄弱

第二周：
  "二分查找也出问题了"
  → 智能体："注意，你上次冒泡排序也是在循环条件上栽的，
      这次 while(left <= right) 再检查一下？"
  → 学生："卧槽你怎么记得"
```

**用户身份**：前端 localStorage UUID，不引入登录系统。比赛场景下同设备足够；清缓存会丢失身份，属于可接受的权衡。

## 四、Coze 侧搭建

| 组件 | 用途 |
|------|------|
| **多智能体 Bot** | 入口 Bot 负责路由分派：数据追问专家 / 诊断专家 / 算法讲解专家 |
| **知识库** | ① Java 标准库文档 + 常见错误速查 ② 算法 SVG 动画模板（按算法类别索引） |
| **Workflow** | ① 复杂度分析 ② 动画生成（标签匹配 → 模板检索 → LLM 填空 → 输出 SVG） |
| **长期记忆** | 自动提取学生薄弱点，跨会话延续教学上下文 |
| **用户变量** | 结构化存储学习进度（技能等级、已学算法、常见错误标签） |

调用方式：后端通过 [Coze Java SDK](https://github.com/coze-dev/coze-java) 统一调 Bot API 和 Workflow API，前端不接触 Coze Token。每次调用传入 `user_id`（前端 localStorage UUID）。
